## <a id="what-is-an-orphan-file"></a> 🤔 什么是“孤立文件”？

使用相机的 JPG + RAW 双格式拍摄时，同一张照片通常会同时保存为两种文件：JPG 便于浏览和分享，RAW 则保留更多原始影像数据，方便后期处理。例如：

```text
IMG_0001.JPG
IMG_0001.CR3
```

如果在相机内挑片、导入照片时遗漏了部分文件，或以前手动清理过其中一种格式，就可能出现只剩下一侧的情况。此时，留下来的文件便称为**孤立文件**。

| 文件夹中的情况 | 文件状态 | 软件如何处理 |
| :--- | :--- | :--- |
| 有 JPG，缺少同名 RAW | 孤立 JPG | 列出供用户检查，确认后才移入回收站 |
| 有 RAW，缺少同名 JPG | 孤立 RAW | 列出供用户检查，确认后才移入回收站 |
| JPG 和 RAW 都存在 | 配对完整 | 不会被选中删除 |

软件会扫描指定文件夹，以**文件基础名**（不含扩展名的文件名部分）作为配对依据，找出缺失的那一侧。扫描范围既可以限定为当前文件夹，也可以扩展到指定层级或全部子文件夹。

### 两种清理界面

软件提供两种查看 JPG / RAW 配对情况的方式。通过应用栏中的「界面」选项即可切换，软件会记住您的选择，下次启动时沿用。

#### 1. 经典界面

只显示识别出的孤立文件，并列出文件名、文件类型、大小和所在文件夹等信息。适合希望直接查看待清理文件、快速完成筛选的场景。

#### 2. 配对对比界面

将同一张照片对应的 JPG 和 RAW 放在同一行，哪一侧缺失可以直接看出来。

| 配对状态 | 行标记 | 含义 |
| :--- | :--- | :--- |
| JPG 和 RAW 都存在 | **绿色** | 配对完整，不属于可删除项目 |
| 有 RAW，缺少 JPG | **黄色** | 缺 JPG，现有 RAW 属于孤立文件 |
| 有 JPG，缺少 RAW | **红色** | 缺 RAW，现有 JPG 属于孤立文件 |

对比界面还提供以下功能：

- **「处理」列：** 直接说明当前行是否会被删除，并区分已勾选的孤立文件、已取消勾选的文件、完整配对，以及因 RAW 格式不在当前匹配范围内而受到保护的文件。
- **可点击的状态图例：** 点击「齐全」「缺 RAW」或「缺 JPG」，即可筛选出对应状态的记录；再次点击当前状态可恢复全部记录。图例同时实时显示各类数量。
- **「只显示缺失」开关：** 隐藏已经配对完整的记录，只查看存在缺失的照片。
- **表头排序：** 点击 JPG 文件名、RAW 文件名、所在文件夹、状态或处理列即可排序；再次点击同一表头可反转顺序，▲/▼ 表示当前排序方向。
- **默认排序顺序：** 优先显示缺 RAW，其次显示缺 JPG，配对完整的记录排在最后。同一状态内按文件名排序。
- **统一的勾选规则：** 只有存在孤立文件的行可以勾选。已配对完整的记录，以及因格式不匹配而受到保护的记录，不能参与普通删除。
- **标记方式可选：** 可以使用整行背景色标记，也可以只改变文字颜色。使用背景色标记时，文字颜色仍保持主题原有颜色，便于阅读。

## <a id="quick-start"></a> 🚀 快速开始

前往 **[GitHub Releases 下载页面](https://github.com/KILLSTARSX/Jpg-Raw-Pair-Cleaner/releases/latest)** 下载最新版本。软件支持 Windows 10 和 Windows 11。发布的程序为绿色单文件版，无需安装，也不需要额外运行环境。

### 清理孤立 JPG / RAW 文件

1. 点击「浏览…」，选择需要检查的照片文件夹，软件会自动开始扫描。
2. 在经典界面或配对对比界面中检查扫描结果；不希望删除的文件，取消勾选即可。
3. 根据需要选择删除范围（仅 JPG、仅 RAW 或全部），然后点击「删除」。
4. 仔细检查确认窗口，明确点击「删除」后，选中的文件才会被移入 Windows 回收站。

### 整理 JPG / RAW 文件

1. 点击应用栏中的「分类整理」，打开独立的整理窗口。
2. 选择来源文件夹、目标根目录和分类方式。来源文件夹默认使用主界面当前选择的文件夹。
3. 查看自动生成的文件夹卡片和统计信息，根据预期的目录结构调整相关选项。
4. 点击「开始整理」，再次核对确认窗口列出的整理方案，确认无误后执行。

更详细的操作说明请参阅 [使用说明书.txt](使用说明书.txt)。

## <a id="photo-organizer-v61"></a> 🗂️ 分类整理（v6.1）

「分类整理」是一个独立的文件归档工具，用于将照片按指定规则整理到不同文件夹中。它**不进行 JPG / RAW 配对，不执行孤立文件清理，也不会删除照片**；只会按照您设置的目标位置移动或复制 JPG 和 RAW 文件。

### 分类整理选项

| 选项 | 说明 |
| :--- | :--- |
| **来源文件夹** | 需要整理的文件夹。默认使用主界面当前选择的文件夹，也可以重新指定。 |
| **目标根目录** | 用于存放新建分类文件夹的位置。留空时，分类文件夹会直接创建在来源文件夹内；也可以另选位置，将整理结果存放到其他目录。 |
| **JPG / RAW 目标目录** | 默认创建名为 `JPG` 和 `RAW` 的文件夹。可以修改目录名称，也可以直接填写完整路径，将某一类文件放到指定位置。 |
| **分类方式** | **按格式分类（默认）：** JPG 进入 JPG 目录，RAW 进入 RAW 目录。**按相机品牌分类：** RAW 文件进一步按照相机品牌和文件后缀分配到不同子目录。 |
| **RAW 文件夹命名** | 在品牌分类模式下，可以从五种命名方式中选择：后缀 + 品牌（默认）、仅后缀、品牌放在括号内、仅品牌，或直接以文件后缀作为文件夹名。选项旁边会实时显示生成的目录名称示例。 |
| **复制（保留原文件）** | 默认关闭，即执行移动操作。勾选后改为复制，来源文件会保留在原位置。 |
| **包含子文件夹** | 默认关闭，只处理当前来源文件夹这一层。开启后，也会处理其子文件夹中的受支持照片。 |

RAW 子文件夹命名示例：

| 命名方式 | 示例 |
| :--- | :--- |
| 后缀 + 品牌（默认） | `RAW(RW2松下)`（英文界面示例：`RAW(RW2Panasonic)`） |
| 仅后缀 | `RAW(RW2)` |
| 品牌放在括号内 | `RAW(松下)`（英文界面示例：`RAW(Panasonic)`） |
| 仅品牌 | `松下`（英文界面示例：`Panasonic`） |
| 仅以文件后缀作为目录名 | `RW2` |

品牌名称会根据软件当前使用的语言进行本地化显示。因此，最终生成的文件夹名称会受到界面语言和所选命名方式的影响。

### 实时预览与操作流程

整理方案会自动生成，整个过程**不需要单独点击「预览」按钮**。

1. **选择整理选项。** 修改来源目录、目标目录、分类方式、命名规则或其他设置时，预览内容会自动更新。尚未选择来源文件夹时，预览区会提示需要先完成的操作。
2. **检查整理方案。** 顶部汇总区域显示文件总数、总大小和目标文件夹数量；下方则为每个目标文件夹显示一张卡片，列出目标路径、文件数量、文件大小、JPG / RAW 数量、示例文件名及占比条。预览只读取文件信息，不会移动或修改任何文件。
3. **确认执行。** 点击「开始整理」后，软件会弹出确认窗口，汇总即将创建的文件夹及需要处理的文件数量。请核对无误后再继续。
4. **查看整理结果。** 操作完成后，预览区域会切换为结果卡片，显示已移动或已复制的文件数量；如有失败项目，会逐条列出原因。返回主界面后，软件会自动重新扫描。

### 文件处理安全机制

- **不会直接覆盖同名文件：** 如果目标位置已经存在另一个同名文件，新文件会自动改名，例如 `IMG_0001 (1).JPG`。
- **跳过已经整理到位的文件：** 文件如果已经位于对应的目标文件夹中，会自动跳过，避免重复执行时再次搬动。
- **避免重复扫描目标目录：** 如果目标文件夹位于来源文件夹内部，扫描时会自动跳过该目标目录，防止刚整理进去的文件再次被当作待整理文件。
- **DNG 格式处理：** `.DNG` 被多个相机品牌共用，无法始终可靠地判断具体品牌，因此按品牌分类时统一归入 `RAW(DNG)`。
- **照片格式范围：** JPG 包括 `.jpg` 和 `.jpeg`；RAW 则覆盖软件能够识别的全部 RAW 后缀。

## <a id="supported-camera-brands--raw-formats"></a> 📸 支持的相机品牌与 RAW 格式

软件内置 **15 个相机品牌配置**。品牌名称会根据界面语言自动本地化，例如 Panasonic 在不同语言下可能显示为 `Panasonic`、`松下 Panasonic` 或 `パナソニック Panasonic`。

| 相机品牌 | 可识别的 RAW 后缀 |
| :--- | :--- |
| 松下 Panasonic | `.RW2` |
| 佳能 Canon | `.CR3` / `.CR2` / `.CRW` |
| 尼康 Nikon | `.NEF` / `.NRW` |
| 索尼 Sony | `.ARW` / `.SR2` / `.SRF` |
| 富士 Fujifilm | `.RAF` |
| 奥林巴斯 Olympus | `.ORF` |
| 宾得 Pentax | `.PEF` |
| 适马 Sigma | `.X3F` |
| 三星 Samsung | `.SRW` |
| 理光 Ricoh | `.DNG` |
| 徕卡 Leica | `.DNG` |
| 哈苏 Hasselblad | `.3FR` |
| 飞思 Phase One | `.IIQ` |
| 玛米亚 Mamiya | `.MEF` |
| 利图 Leaf | `.MOS` |

其他格式识别规则：

- **自动识别：** 自动检测所选文件夹中实际存在的 RAW 文件后缀。
- **自定义格式：** 支持手动输入多个 RAW 后缀，以英文逗号分隔，例如 `.rw2,.dng`。
- **大小写不敏感：** 文件扩展名不区分大小写。
- **格式不匹配保护：** 如果手动选择的相机品牌与实际扫描到的 RAW 文件格式不符，软件会保护这些文件，不会错误地将其作为有效配对对象参与普通清理或删除。
- **RAW 内嵌缩略图：** 六个主要相机品牌的 RAW 文件支持提取内嵌预览图。其他 RAW 格式可能显示后缀占位框；无法读取的 EXIF 字段会显示为 `--`。

## <a id="safety-notes"></a> ⚠️ 安全说明

| 项目 | 安全机制 |
| :--- | :--- |
| **清理删除** | 清理时选中的文件会被移入 **Windows 回收站**，通常可直接从回收站还原。 |
| **永久删除** | 清理流程不调用永久删除操作。 |
| **已配对文件** | 配对完整的 JPG / RAW 不属于普通清理的可选删除对象；对比界面中只有孤立文件行可以勾选。 |
| **格式不匹配** | 不属于当前所选匹配格式的 RAW 文件会受到保护；如需强制删除，必须经过单独的二次确认。 |
| **误触保护** | 自绘确认窗口没有系统标题栏的「×」关闭按钮，默认操作为「取消」。 |
| **单文件处理失败** | 某个文件处理失败不会中断其余文件的操作。软件会列出失败项目及原因；文件被占用时会自动等待并重试一次。 |
| **分类整理重名处理** | 目标位置已有文件时不会直接覆盖，而是自动为新文件添加编号后缀。 |
| **移动与复制** | 分类整理默认采用移动方式。需要保留来源文件时，请勾选「复制（保留原文件）」。开始前务必检查实时预览和确认摘要。 |

> **请特别注意：**「清理」与「分类整理」是两项独立操作。清理会将选中的孤立文件移入回收站；分类整理则会按照指定目录移动或复制文件。执行分类整理前，请务必检查预览方案和确认摘要。

## <a id="faq"></a> ❓ 常见问题

| 问题 | 回答 |
| :--- | :--- |
| **清理删除是永久删除吗？** | 不是。清理操作会将选中的文件移入 Windows 回收站，通常可以从回收站还原。 |
| **已经配对完整的 JPG / RAW 也会被删除吗？** | 普通清理不会。配对完整的文件不会被列为可勾选删除对象。 |
| **分类整理会删除文件吗？** | 不会。分类整理只会将 JPG / RAW 移动或复制到您指定的目标位置，不会执行孤立文件清理，也不会将文件移入回收站。 |
| **分类整理时怎样保留原文件？** | 打开「分类整理」，勾选「复制（保留原文件）」即可。复制模式会将文件复制到目标位置，来源文件保持不动。 |
| **目标文件夹中已经有同名文件怎么办？** | 软件不会覆盖已有的不同文件，而是自动给新文件添加编号后缀，例如 ` (1)`。已经位于对应目标文件夹中的文件会被跳过。 |
| **分类整理默认会处理子文件夹吗？** | 默认不会，只处理当前来源文件夹这一层。需要同时整理子文件夹时，请勾选「包含子文件夹」。 |
| **RAW 文件可以显示缩略图吗？** | v6.0 起支持提取六个主要相机品牌 RAW 文件内嵌的 JPEG 预览图。部分 RAW 格式（如适马 X3F）可能无法提取缩略图，此时会显示对应的格式占位框。 |
| **软件支持哪些格式？** | 支持 JPG / JPEG，以及[支持的相机品牌与 RAW 格式](#supported-camera-brands--raw-formats)一节列出的 RAW 后缀，同时也支持自定义 RAW 扩展名。 |
| **为什么 RAW 文件提示格式不匹配？** | 文件后缀与当前选择的相机品牌或自定义格式不一致。可以切换到「自动识别」，或选择正确的品牌 / 后缀。格式不匹配的文件会受到保护，不参与普通清理。 |
| **如何切换界面语言？** | 使用应用栏中的「语言」选项即可切换。首次启动时软件会检测系统语言，之后以您手动选择的语言为准；不支持的系统语言默认使用英语。 |
| **如何切换主题？** | 使用应用栏中的「主题」选项，在浅色和深色主题之间切换。默认跟随 Windows 应用主题。 |
| **支持哪些操作系统？** | 目前支持 Windows 10 和 Windows 11。 |

## <a id="development-notes"></a> 🛠️ 开发历程与心得

这个项目最初是我用 Python + tkinter 搭建的。后来，我陆续加入了 Pillow 图像处理、多线程、多语言支持和主题系统。功能不断增加，软件体积却一直在缩小：从最初的 27.4 MB，降到 16.2 MB，再到 11.6 MB。每次更新，我都希望在增加实用功能的同时，让程序变得更精简。

不过，Python 打包方案本身存在一定的体积和启动开销。解释器、GUI 运行环境以及图像处理模块都有不可避免的基础占用，继续优化的空间已经越来越有限。反复权衡之后，我决定在 v6.0 中彻底重构整个程序，改用 **C++17 + Windows 原生 Win32 API** 从头实现。

这次重构并不只是把原来的代码换一种语言。圆角卡片、药丸形按钮、滚动条、滑块和下拉框等界面控件，都需要重新绘制和实现；多语言、DPI 缩放、浅色 / 深色主题、图像解码、RAW 内嵌缩略图提取、EXIF 读取，以及 Windows 回收站操作，也都需要通过原生 API 和程序代码重新整合。过去在 Python 中可以直接调用的现成库，到了 C++ 里，很多工作都要重新完成。

最终，程序体积从 27.4 MB 降到了约 623 KB，只剩初版的 2% 左右；实测启动时间也从 1–2 秒缩短到 218 毫秒。对我来说，这次重构的目标从来不是为了缩小体积而删减功能，而是在**保留功能和界面体验的前提下，让软件更轻、更快**。

到了 v6.1，我又把开发重点从照片清理和配对对比延伸到了日常照片整理。新增的分类整理功能围绕一个实际使用流程设计：选择来源和目标位置，查看自动生成的整理方案，确认后执行，最后检查处理结果。我希望用户在真正移动或复制文件之前，就能清楚知道文件将被放到哪里、会创建哪些目录，尽量避免操作过程中的不确定性。

这款软件从一开始就坚持免费、非商业化。我开发它，一方面是为了解决自己日常使用中遇到的问题，另一方面也希望让配置不高的电脑，同样能用上轻便、顺手且体验完整的工具。我始终认为，软件更新不应该只是不断堆叠功能，更应该让实际体验持续变好：功能可以增加，但程序不应因此变得臃肿；运行效率要提升，界面体验也不应该被牺牲。AI 工具也帮助我完成了部分重构和重复性开发工作，但贯穿整个项目的想法一直没有变：**把用户体验放在首位。**
